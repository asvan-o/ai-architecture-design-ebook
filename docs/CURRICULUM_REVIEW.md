## 3. 판단·검증 분류

포괄적인 “전문가 검토 필요” 표시는 사용하지 않고 다음처럼 나눴다.

| 분류 | 적용 범위 |
| --- | --- |
| 수강생 전문 판단 | 공간디자인 방향, 결과 선별, 조직의 실제 업무 절차 등 수강생 또는 담당자가 판단할 항목 |
| 강의 전 사실 검증 | 도구 기능, 강의 예시, 실무 범위 문구를 강의 전에 실제 환경·검토 자료와 대조할 항목 |
| 추가 출처 확인 | 외부 이미지·영상·문서의 출처, 라이선스, 공개·배포 범위를 확인할 항목 |
| 법규·구조·소방 등 해당 전문가 판단 | 법규, 구조, 소방, 접근성, 자재 성능, 시공 가능성처럼 해당 자격·전문 분야의 판단이 필요한 항목 |

기존 “전문가 판단 필요” 36개 표시는 위 의미에 따라 재분류했다. 기존의 일반적인 오류 확인 자리인 “추가 검증 필요”는 출처 확인이나 전문 판단과 구분되는 상태로 남겨 두었다.

## 5. 5·6차시, 7·8차시 중복 검토

### 5차시와 6차시

- 공통 입력: 메모, 요청, 참고자료를 원문 근거와 함께 구조화한다.
- 5차시의 고유 역할: 반복되는 운영 문서를 결정·미결·담당업무와 비교표로 정리하고 원문 추가 오류를 찾는다.
- 6차시의 고유 역할: 클라이언트 의뢰를 확정·희망·미확정 조건으로 나누고 질문과 디자인 브리프 초안을 수강생 전문 판단으로 수정한다.
- 결론: 차시를 합치지 않는다. 공통 원문 대조 템플릿만 공유하는 것이 실행 가능하다.

### 7차시와 8차시

- 공통 산출: 수정 전후 이미지와 변경 기록.
- 7차시의 고유 역할: 재료·조명·가구를 바꾸면서 공간의 고정 요소를 통제한다.
- 8차시의 고유 역할: 클라이언트 코멘트를 분류하고 우선순위·추가 질문·변경 이력·제안판으로 바꾼다.
- 결론: 7차시 결과 이미지를 8차시의 가상 피드백 입력으로 이어 쓸 수 있다. 학습 판단은 서로 달라 차시는 유지한다.

## 6. 9·10차시 도구 실현 가능 범위

### 9차시 Gemini·Nano Banana

Google의 현재 공식 문서는 Gemini 이미지 모델이 텍스트와 이미지를 입력으로 받아 이미지 생성·편집과 대화형 수정을 지원한다고 설명한다. 따라서 참조 이미지를 바탕으로 여러 후보를 만들고 사람이 불일치를 비교·선별하는 골격은 실행 가능하다.

다만 공식 문서는 여러 시점에서 완전히 동일한 건축물, 치수, 창호, 재료를 보장하지 않는다. 9차시의 목표는 “동일성 생성”이 아니라 “일관성 관리와 제외 판단”으로 유지한다. 실제 사용 모델, 입력 이미지 수, 해상도, 저장·권리 조건은 강의 전 다시 검증한다.

- 공식 확인: [Gemini API 이미지 생성·편집](https://ai.google.dev/gemini-api/docs/image-generation)
- 모델 목록: [Gemini 모델](https://ai.google.dev/gemini-api/docs/models)

### 10차시 Gemini 도면·PDF 분석

Google의 현재 공식 문서는 PDF 안의 텍스트, 이미지, 다이어그램, 차트, 표를 함께 이해하고 구조화된 정보를 추출할 수 있다고 설명한다. 따라서 교육용 PDF에서 “보이는 공간명·표기 정보 후보”를 추출하고 원본과 대조하는 실습은 가능하다.

이 지원 범위는 정확한 CAD/BIM 해석, 치수 검증, 법규·구조·소방·접근성·시공 판단을 보장하지 않는다. 비뚤어지거나 흐린 스캔은 판독 품질을 낮출 수 있다. 결과를 `맞음 / 오독 / 판독 불가 / 추가 질문`으로 분류하고 원도면과 대조하며, 고위험 판단은 해당 전문가에게 남긴다.

- 공식 확인: [Gemini API 문서 이해](https://ai.google.dev/gemini-api/docs/document-processing)

## 7. 12·13차시 AGY 중복과 실행 가능성

프로젝트에 승인된 AGY 기능 명세, 실제 명령어, 권한 모델, 테스트 환경이 없다. 따라서 현재 단계에서 AGY가 폴더 생성·반복 검사·패키징을 자동 수행한다고 단정할 수 없다.

- 12차시: 프로젝트 구조, 파일명·버전 규칙, 출처·변경 이력, 자료 인덱스를 먼저 “수동으로도 수행 가능한 템플릿”으로 정의한다.
- 13차시: 12차시 구조를 기준으로 규칙 위반·누락을 찾고 상태 보고서를 만드는 “수동 감사 절차”를 우선 유지한다.
- AGY 시연 2개: 실제 환경 검증 기록이 생기기 전까지 선택 자산이며 제작하지 않는다.
- 검증 후 선택지: 한 개의 챕터형 시연 영상으로 병합하거나, 자동화할 수 없는 부분을 수동 절차로 명시한다.

## 11. 검사 기록

- `npm run lint`: 성공 — Astro 50개 파일, 오류 0, 경고 0, 힌트 0
- `npm run typecheck`: 성공 — Astro 50개 파일, 오류 0, 경고 0, 힌트 0
- `npm run validate:content`: 성공 — 14개 차시, 승인 제목·시간, 13개 섹션, 실습 50% 이상, 현재 48개 자산의 필드·연결·공개 조건 확인. 자산 총수는 고정값으로 강제하지 않는다.
- `npm run build`: 성공 — 정적 출력 8페이지. 14개 차시는 모두 `draft: true`이므로 운영 강의 경로·목록·검색 색인에서 제외됨
- 개발 환경 경로 HTTP 확인: 성공 — 홈, 커리큘럼, 1·10·14차시 모두 200. draft 차시 목록과 전문 검토 범위 표시 확인
- 운영 출력 확인: 성공 — 강의 상세 0페이지, 홈·커리큘럼·검색 색인에 draft 강의 링크 0건

외부 `reference-only` 자산은 학생용 MDX에서 제거하고 매니페스트와 강사용 감사 기록에만 유지했다. 검증 스크립트는 이 자산이 학생용 MDX에 연결되면 실패하도록 하며, 그 밖의 자산은 소유 차시에서 정확히 한 번 연결되는지 확인한다.
