첨부한 교육용 가상 제안요청서(RFP)를 분석해 주세요.

목표는 RFP를 대신 작성하거나 새로운 설계안을 만드는 것이 아니라,
문서에 적힌 요구조건을 디자인 작업에 사용할 수 있도록 근거와 함께 분류하는 것입니다.

다음 항목으로 구분해 표로 정리해 주세요.

1. 프로젝트 목적과 대상 범위
2. 문서에 직접 명시된 필수 요구사항
3. 유지해야 하는 기존 조건
4. 과업에 포함되는 범위
5. 과업에서 제외되거나 별도 협의가 필요한 범위
6. 수치로 제시된 성능·운영 조건
7. 문서만으로 확인할 수 없는 정보
8. 발주기관에 추가로 확인해야 할 질문
9. 제안서 제출·평가·계약 등 행정 및 입찰 조건
10. 디자이너가 대안으로 제안할 수 있는 항목
11. 구조·소방·전기·기계·접근성·시공 등 해당 전문가 확인이 필요한 항목

각 항목에는 다음 정보를 함께 표시해 주세요.

- RFP 페이지, 장·절과 요구조건 ID(REQ ID)
- 근거가 되는 짧은 원문 인용
- 원문에서 직접 확인되는 내용과 사용자의 해석을 분리한 설명
- 정보 유형: RFP 직접 요구 / 제약조건 / 제외 범위 / 행정·입찰 / 미확정 / 디자인 제안
- 확인 상태
- 디자인 작업에 미치는 영향
- 다음 행동: 브리프 반영 / 발주처 질의 / 전문가 확인 / 대안 제안

중요 규칙:

- RFP에 없는 면적, 치수, 구조, 예산, 일정, 재료, 설비와 법규 조건을 사실처럼 추가하지 마세요.
- 문서의 요구사항과 새롭게 제안한 아이디어를 섞지 마세요.
- 새로운 아이디어를 제안할 경우 반드시 ‘디자인 제안’으로 표시하세요.
- 표, 평면도, 각주 또는 작은 글자를 정확히 판독할 수 없다면 추정하지 말고 ‘판독 불가’ 또는 ‘미확정’으로 표시하세요.
- 페이지, 장·절, REQ ID와 짧은 원문 근거를 찾지 못한 내용은 확정 조건으로 표시하지 마세요.
- 제안서 제출·평가·계약 같은 행정·입찰 조건과 공간 디자인 요구를 분리하세요.
- 구조·소방·전기·기계·접근성·법규·시공 적합성을 판정하지 말고 해당 전문가 확인 항목으로 분리하세요.
- 실제 회사 자료, 비공개 RFP, 개인정보, 기업 기밀 또는 사용 권한이 없는 도면을 입력 자료로 요구하지 마세요.
- 결과를 사용하기 전에 사람이 RFP 원문의 페이지·절·REQ ID와 짧은 근거 문장을 대조해야 한다고 안내하세요. <!-- validation-key: rfp-source-traceability -->
- 정확한 근거를 찾을 수 없는 내용은 ‘미확정’ 또는 ‘추가 확인 필요’로 표시하세요.
- 마지막에는 디자인 브리프 초안을 다음 구조로 정리해 주세요.

[디자인 브리프 초안]
- 프로젝트 목표
- 주요 사용자와 활동
- 해결해야 할 핵심 문제
- 필수 공간과 기능
- 수치·성능 요구조건
- 유지해야 할 기존 조건
- 변경할 수 없는 조건과 제외 범위
- 디자이너가 제안할 수 있는 범위
- 미확정 정보와 발주처 질의
- 전문가 확인 항목
- 제4차시에서 도출할 서로 다른 공간 운영 대안의 평가 기준
- 출처 추적 정보: 페이지·절·REQ ID, 확인 상태, 사실·가정·제안 구분

디자인 대안의 구체적인 이름과 방향은 임의로 확정하지 말고,
RFP 분석을 바탕으로 수강생이 도출할 수 있도록 평가 기준만 제안해 주세요.
