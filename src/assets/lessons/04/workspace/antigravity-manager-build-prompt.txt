node --version
npm --version
where node

- 이번 수업에서는 설치 환경 차이를 줄이고 같은 결과를 재현하기 위해 Node.js 22.x LTS로 통일합니다.

- Node.js 24가 잘못된 버전이거나 항상 실패한다고 단정하지 마세요. 이 프로젝트에서만 수업환경 통일을 위해 22.x를 사용합니다.
- package.json의 engines는 "node": ">=22 <23"으로 지정하세요.

- 파일 내용이나 파일명은 변경하지 않습니다.
- PROJECT 안에 별도의 _INBOX 폴더를 만들지 마세요.

2. ROOT와 프로젝트 범위

예시:

ROOT/
├─ PROJECT_A/
├─ PROJECT_B/
└─ PROJECT_C/

다음 파일은 분류하지 않습니다.

ROOT/test.dwg
ROOT/image.jpg

다음 파일만 자동분류 대상입니다.

ROOT/PROJECT_A/test.dwg
ROOT/PROJECT_A/image.jpg

PROJECT 폴더를 만드는 방법은 두 가지입니다.

- Windows 탐색기에서 ROOT 안에 직접 생성
- 프로그램의 “+ 새 프로젝트”에서 생성

프로그램 실행 중 ROOT에 새 프로젝트 폴더가 생기면 자동으로 감시 대상에 추가하세요.

PROJECT 최상위는 신규 파일 투입 영역입니다. 외부 참조가 설정된 기존 작업파일 세트를 옮겨 놓는 보관 위치로 사용하지 마세요.

5. 안전 규칙

- ROOT 밖의 파일을 읽거나 이동하지 마세요.
- junction과 symlink를 따라 ROOT 밖으로 접근하지 마세요.
- 파일 내용과 파일명은 변경하지 마세요.
- 프로그램은 CAD Xref, Revit Link, SketchUp 외부 파일, 3D Texture, Houdini 외부 참조 등의 경로를 수정하지 않습니다.
- 그러나 DWG, RVT, SKP, MAX, MA, MB, BLEND, 3DM, C4D, HIP 계열 작업파일 자체를 이동하면 상대경로나 링크가 끊어질 수 있습니다.
- 외부 참조가 연결된 작업파일 세트는 PROJECT 최상위 자동분류 투입 영역에 넣지 마세요.
- 참조 관계 유지 여부를 프로그램이 자동 보장한다고 표현하지 마세요.
- 대상 폴더에 같은 이름의 파일이 있으면 덮어쓰지 마세요.
- 이름 충돌 파일은 원래 이름을 유지한 채 98_REVIEW의 충돌 전용 하위 폴더로 이동하고 화면에 이유를 표시하세요.
- 일반적인 미등록 확장자는 OTHER로 보내세요.
- 실제 오류, 충돌, 권한 문제만 REVIEW로 보내세요.
- Unreal Engine의 .uproject처럼 폴더와 함께 작동하는 프로젝트 파일은 자동 이동하지 말고 REVIEW 안내만 남기세요.
- 분류된 폴더를 다시 감시해 무한 이동이 발생하지 않게 하세요.
- 파일 쓰기가 끝나기 전에 이동하지 않도록 chokidar의 안정화 옵션을 사용하세요.

README와 프로그램 화면에 다음 문장을 그대로 표시하세요.

외부 참조(Xref, Link, Texture 등)가 연결된 작업파일 세트는
자동정리 대상에 넣지 마세요.
파일 위치가 변경되면 참조 경로가 끊어질 수 있습니다.

8. 의존성 설치와 재현성

package-lock.json을 반드시 생성하고 보존하세요.

최초 설치는 프로젝트 루트에서 다음 순서로 진행하세요.

1. package.json의 Node engines와 의존성 버전을 확인합니다.
2. npm install을 실행합니다.
3. package-lock.json에 Electron 43.3.0, Electron Forge 7.11.2, chokidar 4.0.3이 기록됐는지 확인합니다.
4. npm start를 처음 실행해 Electron의 공식 바이너리 다운로드와 프로그램 시작을 확인합니다.
5. 첫 실행 후 electron.exe와 path.txt가 생성됐는지 확인합니다.
6. 가능하면 깨끗한 설치 상태에서 npm ci로 재설치하고, 다시 npm start로 실행 검증합니다.

npm install, npm ci 또는 첫 npm start의 Electron 바이너리 다운로드 중 아무 출력이나 파일 변화 없이 약 5분 이상 명확한 진행이 없으면 계속 기다리기만 하지 마세요. 실행 중인 프로세스, npm 로그와 node_modules 상태를 확인한 뒤 원인을 설명하세요.

특히 다음 파일을 확인하세요.

node_modules/electron/dist/electron.exe
node_modules/electron/path.txt

Electron 43에서는 npm install 직후 위 두 파일이 아직 없을 수 있습니다. 첫 npm start 또는 Electron이 제공하는 공식 install-electron 명령이 끝난 뒤 확인하세요. 실패를 수동 ZIP 압축 해제나 임의 복사 스크립트로 우회하지 말고, 정상적인 Node/Electron 조합에서 공식 설치 절차가 성공하도록 해결하세요. 실패한 명령을 성공했다고 보고하지 마세요.
