다음 요구사항에 맞는 Windows용 로컬 프로그램을 실제로 구현하고 테스트해 주세요.

프로그램 이름

- 영문: Design Project Auto Organizer
- 국문: 설계 프로젝트 자동 정리 프로그램

목적

- 사용자가 선택한 하나의 ROOT 폴더 아래에서 여러 설계 프로젝트를 관리합니다.
- 각 PROJECT 폴더 최상위에 새 파일을 넣으면 확장자 규칙에 따라 정해진 하위 폴더로 이동합니다.
- ROOT 바로 아래 파일은 분류하지 않습니다.
- 이미 분류된 하위 폴더 안의 파일은 다시 이동하지 않습니다.
- 파일 내용이나 파일명은 변경하지 않습니다.

반드시 사용할 기술

- Electron
- Node.js
- HTML
- CSS
- JavaScript
- chokidar
- Electron Forge

사용하지 않을 기술

- React
- Next.js
- Express
- 웹 서버
- 클라우드 데이터베이스
- 회원가입·로그인
- Gemini API
- OpenAI API
- MCP
- 외부 서버 전송

기본 프로그램은 API Key 없이 완전히 로컬에서 작동해야 합니다.

1. 프로그램 화면

다음 기능이 있는 단순한 데스크톱 화면을 만드세요.

- ROOT 폴더 선택
- 선택한 ROOT 경로 표시
- 새 프로젝트 생성
- 프로젝트 목록 표시
- 프로젝트별 분류 파일 수 표시
- 최근 자동분류 기록 표시
- 오류와 검토 필요 항목 표시

ROOT 선택값은 로컬 설정에 저장하고 다음 실행 때 복원하세요.

2. ROOT와 프로젝트 범위

예시:

ROOT/
├─ PROJECT_A/
├─ PROJECT_B/
└─ PROJECT_C/

다음 파일은 분류하지 않습니다.

ROOT/test.dwg
ROOT/image.jpg

다음 파일만 자동분류 대상입니다.

ROOT/PROJECT_A/test.dwg
ROOT/PROJECT_A/image.jpg

PROJECT 폴더를 만드는 방법은 두 가지입니다.

- Windows 탐색기에서 ROOT 안에 직접 생성
- 프로그램의 “+ 새 프로젝트”에서 생성

프로그램 실행 중 ROOT에 새 프로젝트 폴더가 생기면 자동으로 감시 대상에 추가하세요.

5. 안전 규칙

- ROOT 밖의 파일을 읽거나 이동하지 마세요.
- junction과 symlink를 따라 ROOT 밖으로 접근하지 마세요.
- 파일 내용과 파일명은 변경하지 마세요.
- CAD Xref, Revit Link, SketchUp·Houdini 참조 경로를 수정하지 마세요.
- 대상 폴더에 같은 이름의 파일이 있으면 덮어쓰지 마세요.
- 이름 충돌 파일은 원래 이름을 유지한 채 98_REVIEW의 충돌 전용 하위 폴더로 이동하고 화면에 이유를 표시하세요.
- 일반적인 미등록 확장자는 OTHER로 보내세요.
- 실제 오류, 충돌, 권한 문제만 REVIEW로 보내세요.
- Unreal Engine의 .uproject처럼 폴더와 함께 작동하는 프로젝트 파일은 자동 이동하지 말고 REVIEW 안내만 남기세요.
- 분류된 폴더를 다시 감시해 무한 이동이 발생하지 않게 하세요.
- 파일 쓰기가 끝나기 전에 이동하지 않도록 chokidar의 안정화 옵션을 사용하세요.

6. 프로그램 생명주기

- 프로그램 실행: 연결된 모든 프로젝트를 한 번 스캔한 뒤 실시간 감시를 시작합니다.
- 최소화(-): 프로그램과 감시를 계속 유지합니다.
- 닫기(X): 모든 watcher를 종료하고 Electron 프로세스를 완전히 끝냅니다.
- 다음 실행: 꺼져 있던 동안 PROJECT 최상위에 들어온 파일을 먼저 스캔한 뒤 감시합니다.
- 트레이나 숨은 백그라운드 프로세스를 만들지 마세요.

7. 구현 구조

- Electron main process와 renderer를 분리하세요.
- contextIsolation을 켜고 preload의 제한된 IPC API만 renderer에 노출하세요.
- 자동분류 규칙과 파일 이동 로직은 UI와 분리해 자동 테스트가 가능하게 만드세요.
- 설정 파일 갱신은 임시 파일 작성 후 교체하는 방식으로 안전하게 처리하세요.
- 오류를 성공으로 보고하지 마세요.

8. 테스트

최소한 다음 자동 테스트를 작성하고 모두 통과시키세요.

- 모든 지정 확장자의 목표 폴더 확인
- 프로젝트 생성과 전체 표준 폴더 생성
- ROOT 바로 아래 파일 미분류
- PROJECT 최상위 파일만 분류
- 이미 분류된 하위 폴더 미감시
- 이미지·영상·문서·알 수 없는 일반 파일 분류
- 동일 이름 충돌 시 덮어쓰기 방지와 REVIEW 이동
- .uproject 자동 이동 금지
- 프로그램 실행 중 새 파일 감지
- 프로그램 종료 후 watcher 종료
- 다음 실행 시 미분류 파일 재스캔
- Gemini API, OpenAI API, API Key, MCP가 기본 프로그램 코드에 없는지 확인

9. 실행과 설치 프로그램

package.json에 다음 명령을 제공하세요.

- npm install
- npm test
- npm start
- npm run make

Electron Forge의 Squirrel.Windows maker를 사용해 Windows 설치 프로그램을 만드세요.

최종 산출물에는 다음이 있어야 합니다.

- 실제 실행 가능한 Electron 프로그램
- 자동 테스트
- README
- package-lock.json
- Design Project Auto Organizer Setup.exe

README에는 다음을 설명하세요.

- Node.js LTS 설치
- npm install, npm test, npm start, npm run make
- ROOT와 PROJECT의 차이
- 파일을 넣을 정확한 위치
- 최소화와 X 종료의 차이
