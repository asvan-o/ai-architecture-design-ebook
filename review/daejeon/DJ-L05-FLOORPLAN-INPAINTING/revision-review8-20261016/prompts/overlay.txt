선택 단계와 첨부 순서
세 단계를 한꺼번에 처리하지 않고 화면에서 선택한 한 단계의 파일만 첨부한다. 직접 실습한 경우에는 같은 역할의 본인 출력 파일로 바꾼다.
① 오피스 가구 4석→6석: PLAN-BASE-01.png → PLAN-BASE-01-result.png → PLAN-BASE-01-marked.png
② 오피스 D2 이동: PLAN-BASE-01-result.png(앞 단계 6석 반영본) → PLAN-BASE-01-door-result.png(6석 유지·D2 이동본) → PLAN-BASE-01-door-marked.png
③ 카페 가구 4석→6석: PLAN-BASE-02.png → PLAN-BASE-02-result.png → PLAN-BASE-02-marked.png
수정 요청은 선택 단계에서 사용한 원문을 함께 제공한다.

목적
생성형 이미지 AI가 비교 선을 새로 그리게 하지 말고, 실제 수정 전후 이미지 연산으로 선 색상 차분 오버레이를 만든다.

맥락
같은 단계의 입력 전체 도면과 그 단계의 전체 재반영본을 비교한다. D2 이동의 수정 전 파일은 원본 4석 도면이 아니라 앞 단계 6석 반영본이다.

입력자료
상단 목록 중 한 단계의 수정 전 전체 PNG·수정 후 전체 PNG·영역 표시본·실제 작업 요청을 사용한다. Python 실행 가능한 ChatGPT 데이터 분석 또는 로컬 코딩 에이전트에 파일을 제공한다. 코드 실행이 불가능하면 이미지 편집기/CAD에서 동일 크기 레이어를 겹치는 절차만 설명한다.

작업 단계
1. 두 파일의 크기·방향·고정 기준점이 일치하는지 실제로 읽는다. 일치하지 않으면 임의 자동 보정하지 말고 재반영 단계로 돌아간다.
2. 실제 코드로 두 파일을 같은 흑백 판정 기준에 적용하고 사용한 선 판정 임계값을 기록한다. 수정 전만 있는 선은 파랑, 수정 후만 있는 선은 자주, 겹치는 선은 회색으로 합성한다.
3. 도면과 같은 크기의 색 중첩 PNG와 범례를 만들고, 변경 영역 안/밖 차이를 따로 집계한다. 안티앨리어싱·압축·선 굵기 차이도 검출될 수 있음을 기록한다.
4. 생성된 색 중첩과 교재 PlanOverlay 슬라이더의 실제 전후 이미지를 함께 보고 D2·벽 접합·가구 수·문자·치수를 사람이 확인한다.

조건·제한
원본이나 결과를 새로 그리거나 확대·축소·회전하지 않는다. 색 차분을 법규·구조·정밀 치수 검증으로 표현하지 않는다. 영역 밖 차이를 자동 삭제해 숨기지 말고 실제 수치를 보고한다.

출력 형식
실제 파일 연산으로 만든 색 중첩 PNG 1개·재현 코드·검사 조건과 차이 집계 기록을 제공한다. 뒤이어 관찰 결과를 의도한 변화 / 유지 확인 / 추가 확인으로 나누고 실행하지 못한 경우 미실행이라고 적는다.

검토 기준
오피스 업무 4석·회의 6석과 카페 하단 2석, 문 이동의 기존 자리 벽 복구·새 D2 한 세트, 창·기둥·치수·공간명이 각각 유지됐는지 원도면으로 대조한다.
