선택 단계와 첨부 순서
세 단계를 한꺼번에 처리하지 않고 화면에서 선택한 한 단계의 파일만 첨부한다. 직접 실습한 경우에는 같은 역할의 본인 출력 파일로 바꾼다.
① 오피스 가구 4석→6석: PLAN-BASE-01.png → PLAN-BASE-01-crop.png → PLAN-BASE-01-ai-raw.png → PLAN-BASE-01-marked.png
② 오피스 D2 이동: PLAN-BASE-01-result.png(앞 단계 6석 반영본) → PLAN-BASE-01-door-crop.png → PLAN-BASE-01-door-ai-raw.png → PLAN-BASE-01-door-marked.png
③ 카페 가구 4석→6석: PLAN-BASE-02.png → PLAN-BASE-02-crop.png → PLAN-BASE-02-ai-raw.png → PLAN-BASE-02-marked.png

목적
생성형 이미지 모델로 도면을 다시 그리지 말고, 실제 이미지 파일 연산으로 부분 수정 결과를 원본 전체 도면의 같은 자리에 합성한다.

맥락
선택한 단계 하나만 처리한다. 오피스 가구 수정은 원본 4석 도면, D2 이동은 앞 단계 6석 반영본, 카페 가구 수정은 카페 원본을 바탕으로 한다. 다른 단계의 파일을 섞지 않는다.

입력자료
상단 단계별 목록 중 하나의 전체 원본·원래 Crop·AI 부분 출력·영역 표시본을 준비한다. 코드 실행과 파일 열람이 가능한 ChatGPT 데이터 분석 또는 로컬 Python 코딩 에이전트에서 실행한다. 파일 연산 기능이 없으면 실행한 척하지 말고 이미지 편집기나 CAD 레이어 작업 절차만 안내한다.

작업 단계
1. 실제 파일의 크기·방향을 읽고 원래 Crop의 고정 벽 교차점·축선으로 전체 원본에서의 위치를 찾는다. 대응점을 둘 이상 확인하지 못하거나 배율이 불명확하면 합성하지 말고 정합 기준을 요청한다.
2. 부분 출력의 고정 기준을 원래 Crop과 맞추고 사용한 배율·이동량·보간 방식·잘라낼 범위를 수치 기록한다. 변형이 커서 맞출 수 없으면 중단한다.
3. 실제 마스크를 만들어 가구 변경 부분 또는 D2의 기존/새 문·개폐호·문자·벽 복구 범위만 붙인다. 표시본의 붉은 선을 도면에 복사하지 않는다.
4. 원본 전체 배열의 복사본에서 허용 마스크 내부만 바꾸고, 영역 밖 배열 차이가 0인지 실제 코드로 검사한다. 원본과 합성본을 다른 이름으로 저장한다.

조건·제한
원본 전체의 크기·방향과 선·문자·치수를 다시 생성하거나 전역 리사이즈하지 않는다. 가구 수정에서는 오피스 업무 4석·D3·탕비와 카페 하단 2석·바를 보존한다. D2 이동에서는 6석을 유지하고 기존 D2를 제거·벽 복원한 뒤 새 문 세트를 넣는다. 성공 여부는 실제 계산 결과로만 보고하고 실패 결과를 완성본으로 쓰지 않는다.

출력 형식
합성한 전체 PNG 1개와 재현 가능한 코드·정합 기록 JSON을 제공한다. 기록에는 입력 파일명·배율·이동량·마스크 범위·영역 밖 변경 개수·중단/완료 상태를 포함한다.

검토 기준
사람이 원본과 합성본을 겹쳐 벽·창·문자·치수와 단계별 좌석 수를 확인한다. 코드의 영역 밖 동일 검사는 치수 정확성·법규 적합성이나 마스크 내부 정답을 보증하지 않는다.
