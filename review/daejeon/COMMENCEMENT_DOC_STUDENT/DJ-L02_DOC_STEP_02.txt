Step 1에서 만든 같은 실습 폴더의 프로그램을 그대로 이어서 보완해 줘. 새 프로그램을 따로 만들지 말고 자동 조립 가능 상태와 사람 확인(검수 대기) 상태를 분리하는 검증 규칙을 추가해 줘.

[Step 2 추가 구현 사항]
1. 규칙·검증 파일(app/validator.js, app/rules.json):
   - 모든 조건이 충족되면 상태를 "자동 조립 완료"로 판정하고, 하나라도 어긋나면 임의로 값을 지어내지 말고 "사람 확인(검수 대기)"로 분류해 구체적인 누락·충돌 사유 목록을 반환해 줘.
2. 반드시 잡아야 할 사람 확인(검수 대기) 조건:
   - 필수 항목 누락: 용역명, 발주처, 계약일·착수일·준공예정일·제출일, 사무소명, 개설신고번호, 대표자, 책임기술자 성명·건축사 자격번호 빈칸(자격번호·등록번호 임의 생성 절대 금지)
   - 날짜 역전·충돌: 준공예정일이 착수일자보다 빠른 경우, 계약일자가 착수일자보다 늦은 경우 경고
   - 변경착수계 조건 누락: 신고 구분이 "변경착수계"인데 변경 사유(changeReason)나 당초 계약 기준(previousSummary)이 비어 있는 경우
   - 부가세 미확정: 부가세 구분이 "미확정"인 경우
   - 참여기술자 명단 행의 성명·분야·자격번호 누락
3. 확인 방법:
   - 정상 신규착수계 1건, 변경착수계 변경사유·자격번호 누락 1건, 날짜 역전·부가세 미정 1건을 넣어 자동 조립 완료와 사람 확인(검수 대기) 분기가 정확히 나뉘는지 실행 결과로 확인해 줘.
