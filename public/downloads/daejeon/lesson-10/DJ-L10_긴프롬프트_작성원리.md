# 제10차시 · 긴 프롬프트 작성 원리

긴 문장을 외우지 않습니다. 짧은 상황 설명으로 AI에게 초안을 요청하고 필요한 조건을 사람이 다듬습니다. 아래 한 줄 질문은 ChatGPT 등 초안을 만들 AI에게 입력하는 예시입니다. 만들어진 실행 프롬프트는 각 항목의 실행 플랫폼에서 사용합니다.

파일 번호는 작업 순서를 알아보기 위한 이름입니다. 노트북 A의 발주처 원자료(A01~A07)를 정리해 만든 결과 기준서를 A99(결과물 99번)라고 부릅니다. 사람이 검토한 이 기준서를 노트북 B의 첫 입력자료로 그대로 옮길 때 이름 앞부분만 B00(출발점 00번)으로 바꿉니다. A99와 B00은 내용이 100% 같은 파일입니다. 노트북 B에서 조건과 공식 법규를 대조해 만든 결과 체크리스트는 B99라고 부릅니다. 99는 결과물 구분 번호이며 최종 법적 적합성 승인이라는 뜻이 아닙니다.

## 원자료를 분석하기 전 공통 규칙 정하기

실행 파일: L10-A00_프로젝트_원자료_분석_공통규칙.txt

- 실행 플랫폼: NotebookLM A · 프로젝트 조건 정리
- 준비·실행: 프로젝트 PDF 8개(A01~A07, 배치도 2개 포함)를 노트북 A에 넣고 먼저 이 규칙을 입력합니다.
- 하는 일: 새로 지을 건물과 옆 부지 기존 건물의 정보가 섞이지 않도록 자료를 읽는 기준을 정합니다.
- 구체적인 이유: 자료 코드와 확인 위치, 추정 금지, 신축·기존시설 구분을 따로 적어야 AI가 출처가 다른 수치를 한 프로젝트의 사실처럼 합치는 일을 줄일 수 있습니다.
- 바꿀 조건: 내 사업명, 신축·기존시설 구분, 첨부한 실제 원자료 목록을 확인합니다.

AI에게 초안을 부탁하는 말: “내가 발주처 원자료 7종을 넣고 신축 건물의 조건을 정리하려고 해. 옆 부지 기존 건물의 수치가 섞이지 않고 출처와 미확정 사항을 남기도록, 노트북 A에 먼저 넣을 공통 규칙 프롬프트를 짜줘.”

## 각 자료의 역할을 나누고 신축 조건 정리하기

실행 파일: L10-A01_자료역할_구분_프로젝트_조건분석.txt

- 실행 플랫폼: NotebookLM A · 프로젝트 조건 정리
- 준비·실행: 노트북 A에 원자료를 넣고 공통 규칙을 적용한 다음 실행합니다.
- 하는 일: 문서별 역할과 혼동 위험을 먼저 확인한 뒤 사업 목적·대지·규모·필수 공간을 정리합니다.
- 구체적인 이유: 사업 자료와 기존시설 도면은 역할이 다릅니다. 문서 역할표와 프로젝트 분석을 순서대로 요구하고 각 항목에 근거를 붙여야 어떤 문서에서 나온 조건인지 추적할 수 있습니다.
- 바꿀 조건: 사업명, 실제 첨부 문서, 발주처의 최신 질의답변을 확인합니다.

AI에게 초안을 부탁하는 말: “원자료를 읽기 전에 각 문서가 무엇을 확인하는 자료인지 표로 나누고 싶어. 그다음 신축 건물 조건만 출처와 함께 정리하도록 노트북 A에 입력할 프롬프트를 만들어줘.”

## 섞인 수치와 과도한 해석 다시 점검하기

실행 파일: L10-A02_오류와_과도한해석_점검.txt

- 실행 플랫폼: NotebookLM A · 프로젝트 조건 정리
- 준비·실행: 앞 단계에서 작성한 조건 분석과 원자료가 있는 노트북 A에서 실행합니다.
- 하는 일: 계획 면적을 확정값으로 쓰거나 기존시설 수치를 신축 값으로 섞은 부분을 찾습니다.
- 구체적인 이유: 막연히 다시 확인해 달라고 하면 중요한 오류를 지나칠 수 있습니다. 대지 분할, 기존시설 수치, 운영 종목 수와 방 개수, BF 요구 범위처럼 혼동하기 쉬운 항목을 구체적으로 지정합니다.
- 바꿀 조건: 내 자료에서 혼동하기 쉬운 수치·용도·프로그램·인증 요구를 바꿉니다.

AI에게 초안을 부탁하는 말: “방금 정리한 조건에서 계획값을 확정값으로 바꾸거나 기존 건물 정보를 섞은 오류가 걱정돼. 의심 항목을 원자료와 다시 대조하고 미확정으로 되돌리게 하는 검토 프롬프트를 짜줘.”

## 검토한 조건을 같은 형식의 기준서로 정리하기

실행 파일: L10-A02-5_프로젝트_조건_기준서_표정리.txt

- 실행 플랫폼: NotebookLM A · 프로젝트 조건 정리
- 준비·실행: 오류 검토가 끝난 조건을 노트북 A에서 표로 정리하고 사람이 확인합니다. 이 결과를 프로젝트 조건 기준서로 저장합니다.
- 하는 일: 한 행에 하나의 조건·상태·근거를 기록한 기준서를 만들어 노트북 B에 전달합니다.
- 구체적인 이유: 표의 열과 상태값을 고정해야 확정·계획·예시·추가 확인이 뒤섞이지 않습니다. 마지막 표를 보기 좋게 정리하는 과정에서도 AI가 새로운 조건을 넣지 못하도록 제한합니다.
- 바꿀 조건: 실제 확인 내용, 원자료 코드와 페이지, 후속 확인 여부를 채웁니다.

AI에게 초안을 부탁하는 말: “검토를 마친 프로젝트 조건을 다른 노트북으로 옮길 기준서로 만들고 싶어. 조건마다 상태 하나와 출처를 붙이고 새 정보를 추가하지 않는 표 정리 프롬프트를 써줘.”

## 현재 자료로 검토할 수 있는 범위부터 확인하기

실행 파일: L10-B01_현재자료_법규검토_가능범위.txt

- 실행 플랫폼: NotebookLM B · 법규 자료와 조건 대조
- 준비·실행: 노트북 A에서 만든 프로젝트 조건 기준서를 노트북 B로 옮기고, 확인한 공식 법규 조문과 별표를 추가한 뒤 실행합니다.
- 하는 일: 지금 확인할 수 있는 기준과 법규·설계자료가 더 필요한 항목을 나눕니다.
- 구체적인 이유: 법규 문장이 있어도 실제 도면·면적표가 없으면 적용 결과를 판단할 수 없습니다. 기준의 존재, 추가 법규, 추가 설계자료를 나눠 질문하고 도면 없는 적합·부적합 확정을 막습니다.
- 바꿀 조건: 현재 넣은 법규 판본과 실제 확보한 도면·면적표 목록을 확인합니다.

AI에게 초안을 부탁하는 말: “프로젝트 조건 기준서와 지금 확보한 법규만으로 어디까지 검토할 수 있을까? 지금 확인 가능한 것, 별표가 더 필요한 것, 실제 도면이 필요한 것을 나누는 노트북 B용 프롬프트를 짜줘.”

## 보완한 법규 자료로 체크리스트 다시 정리하기

실행 파일: L10-B02_보완자료_반영_법규검토_체크리스트.txt

- 실행 플랫폼: NotebookLM B · 법규 자료와 조건 대조
- 준비·실행: 필요한 조례·조문·별표를 노트북 B에 추가하고 출처·시행일을 확인합니다. 원문에 적힌 보관 자료 코드와 이번 자료 목록의 대응도 확인한 뒤 실행합니다.
- 하는 일: 추가한 공식 근거를 검토 질문·상태·필요 설계자료와 연결한 표를 만듭니다.
- 구체적인 이유: 근거가 추가돼도 곧바로 적합 판정이 되는 것은 아닙니다. 고정된 상태값과 설계자료 열을 두고, 과거 참고책을 현행 법규 근거로 쓰지 못하도록 제한합니다.
- 바꿀 조건: 질문에 필요한 실제 조문·별표, 검토 기준일, 확보한 설계자료를 확인합니다.

AI에게 초안을 부탁하는 말: “빠진 조례와 별표를 추가했어. 어떤 질문을 무슨 근거로 확인해야 하는지, 아직 필요한 도면은 무엇인지 한 표로 다시 정리하되 적합성을 단정하지 않는 프롬프트를 짜줘.”

## 분석 문장의 혼합·누락을 ChatGPT로 재확인하기

실행 파일: L10-X01_분석문_교차검증.txt

- 실행 플랫폼: ChatGPT · 외부 교차검증
- 준비·실행: 노트북 B의 분석문을 복사해 원문의 붙여넣기 위치에 넣습니다. 사람이 검토한 프로젝트 조건 기준서도 함께 준비합니다.
- 하는 일: 한 문장에 섞인 판단, 별표 누락, 계획조건 오해를 찾고 추가 공식 근거를 요청합니다.
- 구체적인 이유: 분석문을 그대로 믿고 요약시키면 같은 오류가 반복됩니다. 문장 분리, 조문과 별표의 역할, 부족한 자료를 따로 확인하게 해야 보완할 일을 찾을 수 있습니다.
- 바꿀 조건: 실제 분석문, 프로젝트 조건 기준서, 원자료의 계획·미확정 상태를 확인합니다.

AI에게 초안을 부탁하는 말: “노트북 B가 쓴 분석을 복사해 줄게. 여러 판단을 한 문장에 섞었거나 별표 없이 결론 낸 부분을 찾아서, 필요한 공식 자료와 추가 확인사항을 알려줄 교차검증 프롬프트를 만들어줘.”

## ChatGPT의 역할을 조사·검증 보조자로 정하기

실행 파일: L11-01_ChatGPT_법규조사_검증_역할설정.txt

- 실행 플랫폼: ChatGPT · 법규 조사·검증 보조
- 준비·실행: 새 법규검토 대화에 노트북 B로 전달할 프로젝트 조건 기준서를 첨부하고 역할부터 지정합니다.
- 하는 일: ChatGPT가 프로젝트 사실을 새로 만들거나 최종 적합성을 단독 확정하지 않도록 합니다.
- 구체적인 이유: 사실 추가 금지, 미확정 상태 보존, 공식 출처 우선, 사람 최종 판단을 각각 명시해야 조사와 판정의 경계가 유지됩니다.
- 바꿀 조건: 검토할 프로젝트 조건 기준서와 기준일을 확인합니다.

AI에게 초안을 부탁하는 말: “너를 이 프로젝트의 법규 조사와 검증 보조자로 쓰려고 해. 첨부 기준서에 없는 사실을 만들지 않고 공식 근거만 찾으며 최종 판단은 사람이 하도록 역할 설정 프롬프트를 작성해줘.”

## 프로젝트 조건에 필요한 공식 법규 찾기

실행 파일: L11-02_조건기준서_공식법규_검색.txt

- 실행 플랫폼: ChatGPT · 공식 법규 웹 검색
- 준비·실행: 역할을 지정한 ChatGPT 대화에 프로젝트 조건 기준서를 준비합니다. 웹 검색이 가능한 환경에서 공식 법규 후보를 조사합니다.
- 하는 일: 체크리스트 작성 전에 어떤 법률·조례·별표가 왜 필요한지 찾습니다.
- 구체적인 이유: 프로젝트 조건 추출 → 법규 분야 분류 → 공식 출처 검색을 구분해야 무관한 법령이 늘거나 적용 전제 없이 결론을 내리는 일을 줄일 수 있습니다.
- 바꿀 조건: 대상 지역, 용도·규모, 기준일과 미확정 조건을 확인합니다.

AI에게 초안을 부탁하는 말: “이 프로젝트 조건 기준서로 어떤 법규를 확인해야 하는지 찾고 싶어. 아직 체크리스트나 적합 판정은 하지 말고, 필요한 법규·관련 조항·공식 링크·추가 정보를 조사할 프롬프트를 짜줘.”

## 기준서와 공식 원문으로 첫 체크리스트 작성하기

실행 파일: L11-03_노트북B_1차_법규검토_체크리스트.txt

- 실행 플랫폼: NotebookLM B · 법규 자료와 조건 대조
- 준비·실행: 노트북 B에 옮긴 프로젝트 조건 기준서와 사람이 확인한 공식 법규 조문·별표를 넣고 실행합니다.
- 하는 일: 프로젝트 조건마다 적용 근거·확인할 내용·부족한 정보를 연결합니다.
- 구체적인 이유: 프로젝트 사실과 법규 근거를 따로 고정하고 표의 항목·결과 상태를 정해야 AI가 없는 조건이나 기준을 보충해 답을 만들어내는 일을 줄일 수 있습니다.
- 바꿀 조건: 현재 기준서, 등록된 공식 법규 판본, 확보한 설계자료를 확인합니다.

AI에게 초안을 부탁하는 말: “노트북 B에 조건 기준서와 공식 법규 원문을 넣었어. 두 자료만 대조해 검토 질문과 근거를 표로 만들고, 판단할 자료가 없으면 추가 확인으로 남길 프롬프트를 작성해줘.”

## 첫 체크리스트를 정답으로 보지 않고 독립 검증하기

실행 파일: L11-04_ChatGPT_독립_교차검증.txt

- 실행 플랫폼: ChatGPT · 공식 법규 독립 웹 검증
- 준비·실행: 프로젝트 조건 기준서와 노트북 B가 만든 첫 체크리스트 두 자료를 ChatGPT에 제공합니다.

## 지적 사항을 사실로 단정하지 않고 체크리스트 보완하기

실행 파일: L11-05_노트북B_체크리스트_보완.txt

- 준비·실행: ChatGPT의 지적 사항을 원문의 붙여넣기 위치에 넣습니다. 확인된 공식 원문이 더 필요하면 먼저 노트북 B에 추가합니다.
- 하는 일: 교차검증에서 지적한 문제를 등록된 공식 근거로 다시 대조해 체크리스트를 고칩니다.
- 구체적인 이유: ChatGPT의 지적도 틀릴 수 있습니다. 지적 자체를 새 공식 근거로 취급하지 않고 맞는 지적·이미 해결된 항목·판단 불가를 구분해야 오류가 다른 AI로 옮겨가지 않습니다.
- 바꿀 조건: 실제 보완 요청, 추가 확보한 공식 근거, 수정한 기준서가 있으면 그 최신본을 확인합니다.

AI에게 초안을 부탁하는 말: “ChatGPT가 지적한 내용을 노트북 B에서 다시 확인하려고 해. 지적을 그대로 사실로 받아들이지 말고 기준서와 공식 자료로 대조해 필요한 부분만 고치게 하는 프롬프트를 작성해줘.”
